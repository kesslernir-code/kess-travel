# כלים מקומיים ל-KESSLER_TRIP

שלושה קבצים חדשים שנועדו לחסוך צילומי מסך ותיאור בצ'אט — הכל רץ מקומית על המחשב הזה, בלי אינטרנט חיצוני ובלי לוגין.

## הקבצים

- **`start_local_server.bat`** — הפעלת השרת המקומי. לחיצה כפולה פותחת חלון שחייב להישאר פתוח בזמן שימוש בטופס או במפה.
- **`local_server.js`** — השרת עצמו (Node.js, ללא תלויות חיצוניות). מאזין על `http://localhost:8787`.
- **`New_Trip_Form.html`** — טופס פתיחת טיול חדש. פותחים אותו ישירות בדפדפן (כפול-קליק).

## איך זה עובד

### פתיחת טיול חדש בלי צ'אט
1. לחיצה כפולה על `start_local_server.bat` — משאירים את החלון פתוח.
2. פתיחת `New_Trip_Form.html` בדפדפן, מילוי הטופס, "שליחה".
3. הטופס שומר קובץ `<יעד>/<יעד>_Trip_Input.md` ישירות בתיקייה.
4. חוזרים לצ'אט ואומרים "תתחיל תכנון ל&lt;יעד&gt;" — קלוד קורא את הקובץ ולא שואל שוב את מה שכבר מולא.

### אישור בחירת נקודות במפה (טאב 4)
1. השרת המקומי צריך להיות פעיל (כמו למעלה).
2. בעמוד `<יעד>_Route_Map.html`, מסמנים את הנקודות הרצויות ולוחצים "נעילת הבחירה הסופית".
3. הבחירה נשלחת אוטומטית ונשמרת כ-`<יעד>/<יעד>_Selection.json`.
4. חוזרים לצ'אט ואומרים "תמשיך" — אין צורך לתאר את הבחירה או לצלם מסך.

### פתיחה אוטומטית של הדשבורד
כל עוד השרת המקומי פועל, ברגע שקלוד יוצר קובץ דשבורד חדש (`<יעד>_KESSLER_TRIP.html`) — הוא נפתח לבד בדפדפן, בלי צורך ללחוץ עליו. זה קורה פעם אחת בלבד, ברגע שהטיול מתחיל (לא בכל פעם שאחד הטאבים מתעדכן), וטיולים ישנים לא נפתחים מחדש כשמפעילים את השרת מחדש.

### אם השרת לא פועל
שני הכלים נופלים בחזרה בעדינות למצב הישן: הודעת שגיאה ברורה על המסך, והאפשרות לתאר את הבחירה/הפרטים בצ'אט כרגיל ממשיכה לעבוד בדיוק כמו קודם. הפתיחה האוטומטית של הדשבורד פשוט לא תקרה — צריך לפתוח את הקובץ ידנית.

## הערות

- הכל נשאר על המחשב הזה בלבד — שום נתון לא יוצא החוצה.
- אפשר לסגור את חלון השרת בכל שלב (Ctrl+C או סגירת החלון) ולפתוח מחדש כשצריך.
- אם הפורט 8787 תפוס על ידי תוכנה אחרת, `local_server.js` לא יעלה — יש לשחרר את הפורט או לשנות את `PORT` בקובץ ואת הכתובות בטופס/במפה בהתאמה.
